## What was deliberately not done — and why

### Not done: `alpha_of_class` opaque → hardcoded
Replacing `opaque alpha_of_class : Set Language → ℝ` with
`fun S => if S = ClassP then √2 else if S = ClassNP then φ+¼ else 0`
would *reduce* honesty. The current opaque-plus-conjecture pattern
transparently encodes that the values are stipulated by the substrate
axiom. A hardcoded case-split would obscure the assumption inside
something that looks definitional. The genuinely correct fix is making
every consumer take `alpha_of_class` as an explicit parameter; this is
a multi-file refactor that needs lake-build verification in the loop.

### Not done: Clay targets wired to mathlib types for NS, YM, Hodge
Mathlib does not yet have:
- Sobolev / Bochner-space Navier–Stokes PDE infrastructure
- Osterwalder–Schrader / Wightman gauge field axioms
- Hodge classes on Calabi–Yau varieties + Chow rings
- Gross–Zagier + Kolyvagin for BSD rank ≥ 1

These are years of upstream community work, not session fixes. RH
already touches `Complex.riemannZeta` via `RHSurjectivityConjecture.lean`;
BSD already touches `WeierstrassCurve`. The others must wait.

### Not done: complete the four sorries in `VAlphaPMap.lean`
Three of the sorries (`toFun` + `map_add'` + `map_smul'`) need a small
mathlib API call to extract Finsupp coordinates from a Submodule.span
element. The fourth (`H_alpha_act_basis_symm` inner-product unfolding)
needs `lp.inner_single_single` + `Complex.ofReal_inj`. Both are routine
mathlib exercises requiring lake-build iteration that I can't do
remotely. The file IS marked clearly: not imported by `PF.lean`, so the
existing 0-sorries claim of the canonical library is preserved.

### Not done: discharge the named open Props
P1 (PolylogEigenvalueConjecture), P4 (RHSpectralSurjectivityConjecture),
P5–P8 (fractal* hypotheses) — these are the actual open mathematical
problems of the framework. No session-scale work can close them; they
require either original research (P1, P4) or multi-year mathlib upstream
(P5–P8). Their status is recorded in `OPEN_PROBLEMS.md`.

### Not done: replace synthetic 143-problem corpus with real data
The parametric refactor in `HundredFortyThreeProblems_Parametric.lean`
provides the right *framework* (real implication instead of tautology).
The substantive fix — supplying real measurements — requires data
acquisition from the project's data layer
(`4_DATA_AND_EVIDENCE/` locally), not a Lean change.
