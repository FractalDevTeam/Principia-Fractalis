### 1. The metric saturates. It discriminates nothing.

`csv.DictReader` over the dataset:

| | |
|---|---|
| data rows | **142** (not 143) |
| distinct values of `fractal_coherence` | **one** |
| rows at `fractal_coherence = 100` | **142 of 142 (100.0%)** |
| rows marked `known_result = Open` | 113 — **all 113 at 100** |
| rows whose `known_result` contains "solved" | 29 — all at 100 |

Every row scores 100, including every one of the 113 open problems. A metric
that returns its maximum on 100% of inputs, open and solved alike, has **no
discriminating power** and cannot be evidence for anything. "100% fractal
coherence across 143 problems" is not a 143-for-143 success rate; it is a
constant.

This also **corrects** the 2026-10-08 provenance pass, which attributed the
high scores to the string-match clamp at script L211-214:

```python
base_coherence = 0.5 + 0.5 * xi
if "solved" in known_result.lower():
    return min(1.0, base_coherence + 0.5)
return base_coherence
```

The clamp is real, but it is not the mechanism for most rows — only 29 of 142
contain "solved", while all 142 score 100. `base_coherence` itself saturates.
The conclusion is unchanged and in fact stronger.

### 2. The quantum result never enters the headline number.

`fractal_coherence` is computed only from `fractal_resonance_function`
(script L196-214): a classical base-3 digit-sum series, `n_max = 300`, summed
as `Σ (cos + i·sin)(π·α·D₃(n)·(1+freq/50)) / nˣ`, scored by
`np.mean([abs(r)**2 for r in res])` (L223).

The backend circuit run — `self.backend.run(optimized_qc, shots=4096)`
(L540, L566) — is a **separate code path whose output is never used in the
coherence score**. So even on genuine quantum hardware, the hardware result
does not contribute to the published figure.

### 3. The preserved dataset cannot substantiate "hardware".

The script has both paths. Hardware (L483-493) needs an `api_token` and
selects `service.backends(simulator=False, ...)`. On any exception, L563-564:

```python
print(f"Error running on IBM Quantum: {e}. Falling back to simulator.")
self.backend = AerSimulator(method='automatic')
```

and the no-token default is `AerSimulator(method='automatic')` (L504).

**The dataset's 22 columns include no `backend`, `device`, `shots`, `qpu` or
`hardware` field.** So whether the 2026-05-23 run executed on an IBM device or
on the local simulator **cannot be determined from the preserved evidence**.
That is the precise and defensible statement. Do NOT assert "it was a
simulator" — assert that the record does not support "hardware", which is
enough, because the burden is on the claim.

### 4. "Solved" in the title is the script's own threshold.

`determine_status(coherence)` at L661-667: `coherence >= 90` → `"Solved"`.
Since all 142 rows are at 100, the script labels all 142 "Solved" — including
the 113 open problems. That is the provenance of the filename
"143 Problems **Solved** On IBM".

### 5. The significance figure has no basis.

ch21 L1112 states `P(all 143 by chance) < 10⁻⁴³` on a 95% baseline. There are
no 143 independent Bernoulli trials — there is one deterministic formula at its
ceiling. On the stated baseline the arithmetic would be `0.95¹⁴² ≈ 7×10⁻⁴`, not
`10⁻⁴³`.

### 6. The dimensions used are not the book's α-skeleton.

Per the 2026-10-08 pass: P-vs-NP `fractal_dimension = 1.618` (φ) against the
book's `α_P = √2`; NS `1.667` (the superseded 5/3) against `α_NS = 3π/2`; YM
`2.15` against 2; Hodge `2.1` against φ. Sourced in-script to "Smale (1998)".
So the run does not even exercise the framework's own values.
