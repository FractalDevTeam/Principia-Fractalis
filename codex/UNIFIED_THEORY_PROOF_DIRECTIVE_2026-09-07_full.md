## §1 Governing objective

The proof of the unified theory is the project's controlling objective. Every campaign, theorem, computation, audit, and publication task is evaluated by whether it **advances, tests, or protects** that objective.

The ξ campaign, finite-height RH, book production, publicity, and empirical corroboration are **not substitutes**. They continue only as bounded supporting programs with explicit relevance.

**Canonical document:** `UNIFIED_THEORY_PROOF_PROGRAM.md` (central theorem, dependency graph, open obligations, countermodel risks, next decisive step).

**Queue gate:** no task enters the active queue unless its ledger entry states one of — (a) the exact unified-theory obligation it advances; (b) the failure mode it tests; (c) the trust or reproducibility property it protects; (d) that it is explicitly non-core and capped by a declared resource budget.

## §2 Completion theorem first

Draft the exact **Lean signature** of the theorem that would constitute mathematical completion of the unified theory. Strongest honest version supported now, plus a weaker currently reachable version.

**No bundled predicates hiding content** (`StructuralLaws`, `PhysicalAdmissibility`, `Correspondence` and similar).

Must expose: foundational assumptions; the constructed universe/structure; the equivalence relation for uniqueness; every claimed sector; every claimed-derived numerical constant; the correspondence statements linking derived structures to established theories; **which conclusions are mathematical and which require empirical premises**.

Deliverables: proposed closed-form signature; weaker reachable signature; field-by-field explanation; list of premises that presently restate a desired conclusion.

Not accepted unless a reviewer can determine the substantive assumptions from `#check @` + unfolded definitions.

## §3 Backward dependency graph

Machine-readable ledger from the completion theorem backward. Every load-bearing node classified as **exactly one** of:

1. definition or convention
2. theorem derived from earlier foundations
3. independently motivated axiom
4. empirical input
5. conditional interface
6. unresolved conjecture
7. recorded-negative or refuted statement

Per theorem: source file, FQN, direct dependencies, `#print axioms` result, closed-term status, rebuilt-from-committed-source status.

Deliverables: `UNIFIED_THEORY_DEPENDENCY_LEDGER.md` (human-readable) generated from a machine-readable companion (`.json`/`.csv`).

**Unknown provenance is a blocker, not a neutral status.**

## §4 α-skeleton rigidity — first mathematical gate

Reconcile r124 (one-parameter family) with r128 (L1–L5-conditional uniqueness). **Per law L1..L5**: unfold fully; earliest independent source; test whether it follows from pre-existing foundations; test whether it imports a target number/structure; remove and survey the surviving model family; countermodel search; verdict — necessary / redundant / derivable / independent / circular.

**No replacement assumption to rescue uniqueness without the same audit.**

Deliverables: adversarial rigidity report — verdicts, dependency paths, countermodels or bounded failed searches, minimal sufficient subsets, residual parameter space after removing each law, strongest non-circular uniqueness theorem currently justified.

No "unique / forced / derived" label until kernel theorem AND premise audit **jointly** support that exact word.

## §5 Sector interfaces

Per claimed sector — geometry/topology, quantum structure, gravitation, cosmology, consciousness, others — one separate **interface theorem** showing how the sector arises from the same foundational object. Interface distinguishes: construction; governing identities; uniqueness/equivalence; numerical specialization; physical interpretation; empirical correspondence.

**Shared notation, a common fitted parameter, and post hoc numerical agreement do not count as unification.**

Sector matrix: rows = claims, cols = construction/derivation/uniqueness/correspondence/empirical/trusted-assumptions. Every green cell links to a theorem name + audit output.

A sector is "derived" only when its interface theorem uses no premise that already contains that sector's target result in equivalent form.

## §6 Two claim ladders — never collapse

- **Mathematical:** definitions → existence → structural laws → rigidity → sector derivations → unified-theory theorem.
- **Empirical:** observable map → preregistered prediction → measurement protocol → data → uncertainty analysis → replication.

Kernel verification is **not evidence** nature instantiates formal premises. Empirical fit is **not proof** of mathematical derivation.

Per physical claim record: theorem name, observable definition, units, dataset, prediction date, uncertainty model, degrees of freedom, prospective/retrospective flag.

"Confirmed prediction" only if fixed **before** relevant data examined and survives the registered decision rule.

## §7 Kernel-trust standard, everywhere

Apply r331b evidence discipline to every load-bearing unified-theory theorem:

- No `sorry`, `admit`, hidden axiom, `Prop := True`, or equivalent bypass.
- No acceptance based solely on build return code.
- Explicit `#print axioms` inspection, judged by absence of `sorryAx` / `ofReduceBool`.
- `#check @` for unconditional claims — a genuinely unconditional theorem shows no binders.
- Exact arithmetic for verdicts; decimals only as diagnostics.
- Explicit treatment of native evaluation, opaque computation, external solvers, generated certificates.
- Committed provenance and clean rebuild from committed source.

Any theorem exceeding `[propext, Classical.choice, Quot.sound]` is **quarantined** from the canonical chain until the extra dependency is explained and approved.

Auto-generated audit target + non-clean report that fails closed.

**One unexplained non-kernel-three axiom blocks the release claim.**

## §8 Adversarial program — equal priority to constructive

Assign equal priority to attempts to break the theory:
- remove assumptions one at a time;
- construct non-isomorphic models;
- search for parameter families;
- test definitional equivalences that reveal relabeling;
- identify vacuous premises and unused hypotheses;
- test consistency between sector interfaces;
- alternate structures producing the same advertised constants;
- formalize recorded-negative claims when they constrain the viable theory.

Log negative results even when they block a preferred narrative.

`UNIFICATION_COUNTERMODEL_LEDGER.md` — successful countermodels, bounded failed searches, what each result proves or does not prove.

**A failed automated search is never described as proof of nonexistence unless the search space is formally exhaustive.**

## §9 Auxiliary campaigns bounded

r331c/d permitted for: reusable verified complex-analysis / numerical-certificate infrastructure; the precisely scoped finite-height theorem; reproducible proof engineering. **Must not delay** the rigidity audit or completion-theorem spec.

Own claim ladder: box → boundary result → count identity → evaluated count → finite-height RH. **Never** promoted as evidence for global RH or for the unified theory absent a separate formal dependency.

Every auxiliary campaign gets: resource ceiling; stopping condition; named reusable deliverable. Exceeding ceiling **auto-pauses and escalates to Pablo**.

## §10 Report format — decisions, not activity

Exact order, one screen when possible, ledgers attached rather than reproduced:

1. Central theorem status
2. What became proved
3. What became disproved or weaker
4. Current blocking obligation
5. Assumption or circularity changes
6. Kernel and rebuild status
7. Decision required from Pablo
8. Next decisive action

If nothing changed: **"No change to the unified-theory proof state."**

## §11 Immediate execution order

1. Freeze and verify the r331b release artifact already in progress; **do not broaden its claims**.
2. Draft the canonical unified-theory completion theorem and its reachable weaker form.
3. Build the backward dependency ledger from that theorem.
4. Execute the α-skeleton rigidity audit as the first decisive mathematical gate.
5. Use the audit verdict to revise the theorem signature and roadmap.
6. Construct and audit the sector-interface matrix.
7. Resume or continue auxiliary campaigns within their approved resource ceilings.
8. Advance empirical work only through preregistered, falsifiable tests with explicit observable maps.

## §12 Prohibited substitutions — none of these constitute proof of the unified theory

- a large theorem or line count
- successful compilation without axiom inspection
- conditional uniqueness whose premises encode the target
- one selected model when a parameter family remains
- numerical coincidence without a derived observable map
- retrospective fit presented as prediction
- finite-height RH
- global RH by itself
- shared terminology across sectors
- a book narrative unsupported by the formal dependency chain

## §13 Definition of success

Mathematical unification is complete only when Lean verifies a **closed, auditable theorem** showing that independently stated foundations determine — up to the explicitly defined equivalence — the common structure and claimed sector interfaces, with every load-bearing assumption exposed and every canonical theorem passing the project's kernel and clean-rebuild gates.

Physical validation remains a separate objective: the resulting formal structure must yield explicit prospective predictions that survive measurement and independent replication.

Until both standards are met: **use exact scope language**. The kernel decides derivability. The dependency audit decides whether the derivation is substantive. Observation decides whether the formal structure describes nature.
